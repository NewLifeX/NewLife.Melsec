## 1. 架构概览

## 2. 协议层设计

### 2.1 FxLinks 协议（已实现）

#### 帧格式

**请求帧（ENQ 05）**

```
字节位置  字段          长度   说明
0        控制码         1     固定 0x05 (ENQ)
1~2      站号           2     ASCII 十六进制，如 "05" 表示站号 5，"FF" 表示广播
3~4      PLC 号         2     ASCII 十六进制，通常 "FF"
5~6      命令码         2     "BR"=位读 / "WR"=字读 / "BW"=位写 / "WW"=字写
7        等待字符       1     ASCII，控制 PLC 响应延迟，通常 "0"
8~12     起始地址       5     ASCII，格式为软元件类型+十进制编号，如 "D0210"、"M0103"
13~14    点数           2     ASCII 十六进制，如 "08" 表示 8 个点
15~16    [数据]         N     仅写命令携带；位写每点 1 字符（"0"/"1"），字写每点 4 字符（十六进制）
末尾      校验和         2     ASCII 十六进制，从站号开始所有字节 ASCII 码累加取低 8 位
```

**示例（读 Y0 起 8 个位）**：
```
05 30 35 46 46 42 52 30 59 30 30 30 30 30 38 36 35
│  ╞════站号═╡ ╞═PLC═╡ ╞BR╡ 等 ╞══Y0000══╡ ╞08╡ ╞校╡
```

**读响应帧（STX 02）**

```
字节位置  字段     长度   说明
0        控制码    1     固定 0x02 (STX)
1~2      站号      2     ASCII
3~4      PLC 号    2     ASCII
5~N      数据      N     位读：每位 1 字符("0"/"1")；字读：每字 4 字符（十六进制）
N+1      ETX       1     固定 0x03
N+2~N+3  校验和    2     ASCII 十六进制
```

**写响应（ACK 06 / NAK 15）**

```
ACK: 0x06 + 站号(2) + PLC号(2)        → 写入成功
NAK: 0x15 + 错误码(2)                 → 写入失败，含错误码
```

#### 校验算法

```csharp
// 从站号字节开始（不含 ENQ），所有字节 ASCII 码累加，取低 8 位
Byte sum = 0;
for (var i = 1; i < frameLength - 2; i++) sum += frame[i];
var checkSum = (sum & 0xFF).ToString("X2");
```

#### 串口参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 波特率 | 9600 | 可配置（1200/2400/4800/9600/19200） |
| 数据位 | 7 | FxLinks 规范 |
| 奇偶校验 | Even | FxLinks 规范 |
| 停止位 | One | FxLinks 规范 |
| 超时 | 3000ms | 可配置 |

#### 地址格式

| 软元件类型 | 编号格式 | 示例 | 说明 |
|-----------|---------|------|------|
| D（数据寄存器） | 十进制 5 位 | D0210 | `D` + 4 位十进制 |
| M（辅助继电器） | 十进制 5 位 | M0103 | `M` + 4 位十进制 |
| X（输入位） | 八进制 4 位 | X0002 | `X` + 4 位八进制 |
| Y（输出位） | 八进制 4 位 | Y0000 | `Y` + 4 位八进制 |
| C（计数器） | 十进制 5 位 | C0010 | `C` + 4 位十进制 |
| T（定时器） | 十进制 5 位 | T0005 | `T` + 4 位十进制 |

### 2.2 MC 协议 3E 帧（待实现）

#### 帧格式（二进制模式）

**请求帧**

```
偏移  字段           长度  说明
0~1   子头           2    固定 0x50, 0x00（3E 帧标识）
2     网络号         1    通常 0x00（本机）
3     PC 号          1    通常 0xFF
4~5   IO 单元号      2    固定 0xFF, 0x03（Q/L/FX5U 系列）
6     通道号         1    通常 0x00
7~8   数据长度       2    Little-Endian，后续字节数
9~10  CPU 时钟       2    固定 0x0A, 0x00
11~12 命令           2    Little-Endian（见命令码表）
13~14 子命令         2    Little-Endian（0x0000=字模式, 0x0001=位模式）
15~   请求数据       N    起始地址(3) + 软元件代码(1) + 点数(2)
```

**读取请求数据区**

```
偏移  字段           长度  说明
0~2   起始软元件编号  3    Little-Endian（字读/位读共用，最大 0xFFFFFF）
3     软元件代码      1    见软元件代码表（0xA8=D, 0x90=M, 0x9C=X...）
4~5   软元件点数      2    Little-Endian，最大 960（字）或 7168（位）
```

**响应帧**

```
偏移  字段           长度  说明
0~1   子头           2    固定 0xD0, 0x00
2     网络号         1
3     PC 号          1
4~5   IO 单元号      2
6     通道号         1
7~8   数据长度       2    Little-Endian
9~10  结束码         2    0x0000=成功，非零=错误（见错误码表）
11~   响应数据       N    字响应：每字 2 字节 LE；位响应：2 点压缩为 1 字节
```

**示例（读 D100 起 4 个字）**

请求：
```
50 00  00  FF  FF 03  00  0C 00  0A 00  01 04  00 00  64 00 00  A8  04 00
子头   网  PC  IO单元  CH  数据长   CPU时  命令WR  子命字   D100起   D代码  4点
```

响应：
```
D0 00  00  FF  FF 03  00  0A 00  00 00  11 00  22 00  33 00  44 00
子头   网  PC  IO单元  CH  数据长   结束码  D100    D101    D102    D103
```

| 批量写入 | 1401h | 0001h | 位软元件写入 | 最大 7168 点 |

|--------|------|------|------|
| SM | 0x91 | 位 | 特殊继电器 |

| X | 0x9C | 位 | 输入继电器（十六进制编号） |

## 3. 驱动层设计

### 3.1 FxLinksDriver（已实现）

**职责**：

1. 持有并复用 `FxLinks` 协议实例（按串口名唯一区分）
2. 实现 `IDriver.Open / Close / Read / Write` 接口
3. 对多节点（多站号）共享同一 `FxLinks` 连接，使用引用计数管理生命周期
4. `BuildSegments` 方法将离散点位按地址排序 → 合并相邻区间 → 按 BatchSize 分批

**批量读取优化（BuildSegments）**

```
原始点位：[D100, D105, D101, D102, D200, D201, D202]

步骤 1：按软元件类型分组
  D 组：D100, D105, D101, D102, D200, D201, D202
  M 组：（空）

步骤 2：按地址排序
  D 组：D100, D101, D102, D105, D200, D201, D202

步骤 3：合并相邻区间（BatchStep = 2）
  区间 1：D100~D105（差值 ≤ 2，合并）→ 读 6 个字
  区间 2：D200~D202（差值 ≤ 2，合并）→ 读 3 个字

步骤 4：按 BatchSize 分批（BatchSize = 4 时）
  批次 1：D100~D103
  批次 2：D104~D105
  批次 3：D200~D202
```

**结果分发（Dispatch）**

将汇聚读取的数组按各点位的相对偏移切分，写入对应 `IPoint` 结果。

### 3.2 MCDriver（待实现）

**设计目标**：与 `FxLinksDriver` 保持相似结构，差异仅在于使用 `MCProtocol`（TCP）替代 `FxLinks`（串口）。

**关键设计决策**：

| 决策点 | 选择方案 | 备选方案 | 选择理由 |
|--------|---------|---------|---------|
| TCP 连接管理 | 长连接 + 自动重连 | 每次短连接 | 工厂环境频繁短连接会触发 PLC 的连接数限制 |
| 帧格式 | 二进制模式优先 | ASCII 模式 | 二进制帧效率更高，Q/FX5U 系列均支持 |
| 依赖 | 纯托管 TCP（System.Net.Sockets） | HslCommunication | 保持 MIT 开源，无商业授权限制 |
| 错误处理 | 结束码非零时抛 MCException | 返回 null | 便于上层区分通信错误和协议错误 |
| 连接共享 | 按 "IP:Port" 为唯一键共享实例 | 每节点独立 | 节省连接数，与 FxLinksDriver 策略一致 |

**类图（规划）**

```
MCDriver : DriverBase, IDriver
  + Link : MCProtocol
  + CreateParameter() : IDriverParameter
  + Open(device, parameter) : INode
  + Close(node) : void
  + Read(node, points[]) : IDictionary<IPoint, Object>
  + Write(node, point, value) : Object
  # BuildSegments(points[]) : MCSegment[]
  # Dispatch(segments, values) : IDictionary<IPoint, Object>

MCProtocol : DisposeBase
  + Address : String               // "192.168.1.10:6000"
  + Timeout : Int32                // 5000ms
  + Open() : void
  + Close() : void
  + ReadWords(devCode, start, count) : UInt16[]
  + ReadBits(devCode, start, count) : Boolean[]
  + WriteWords(devCode, start, values) : void
  + WriteBits(devCode, start, values) : void
  - SendCommand(request) : MCResponse
  - _client : TcpClient

MCMessage : IAccessor
  + SubHeader : UInt16            // 0x0050
  + NetworkNo : Byte              // 0x00
  + PCNo : Byte                   // 0xFF
  + IOUnitNo : UInt16             // 0x03FF
  + ChannelNo : Byte              // 0x00
  + Command : UInt16
  + SubCommand : UInt16
  + DeviceCode : Byte
  + StartAddress : Int32
  + Count : UInt16
  + WriteData : UInt16[]

MCResponse : IAccessor
  + EndCode : UInt16              // 0x0000 = 成功
  + WordData : UInt16[]
  + BitData : Boolean[]

DeviceCodes
  + D   = 0xA8
  + M   = 0x90
  + X   = 0x9C
  + Y   = 0x9D
  ...（完整软元件代码枚举）

MCParameter : IDriverParameter, IDriverParameterKey
  + Address : String              // "192.168.1.10:6000"
  + Timeout : Int32               // 5000
  + Host : Byte                   // 网络号，通常 0
  + BatchStep : Int32
  + BatchSize : Int32
  + BatchDelay : Int32
```

## 4. 公共数据模型

### 4.1 MelsecNode（已实现，两协议共用）

```csharp
public class MelsecNode : INode
{
    /// <summary>节点地址（串口名 COM1 或网络地址 192.168.1.10:6000）</summary>
```

### 4.2 地址解析策略

**FxLinks**（已实现）：

```

输入: "X2"    →  类型=X, 编号=2（八进制）  →  帧地址 "X0002"
输入: "M103"  →  类型=M, 编号=103（十进制）→ 帧地址 "M0103"
```

**MC 协议**（待实现）：


## 5. 关键设计决策

| 决策点 | 方案 | 备选方案 | 选择理由 |
|--------|------|---------|---------|
| 协议实现方式 | 纯托管 .NET，不依赖第三方 | 包装 HslCommunication | MIT 开源，无商业授权风险；利于长期维护 |
| 帧基类 | 分开实现 FxLinksMessage / MCMessage | 共用基类 | FxLinks（ASCII帧）与 MC（二进制帧）差异太大，共用基类反而增加复杂度 |
| 驱动注册 | `[Driver("MelsecFxLinks")]` / `[Driver("MelsecMC")]` | 工厂方法 | 遵循 NewLife.IoT 驱动注册约定 |
| 连接唯一性 | `IDriverParameterKey.GetKey()` 返回 PortName/Address | 全局单例 | 允许同进程连接多台不同 PLC |
| 批量优化单位 | 按软元件类型分组 + 地址区间合并 | 单点逐个读取 | 减少通信次数，提升 10 倍以上采集效率 |
| 错误码 | 单独枚举类（ErrorCodes / MCErrorCodes） | 内联常量 | 便于文档生成和调试时快速定位 |

## 6. 接口设计（驱动层对外 API）

### 6.1 FxLinksDriver 快速上手

```csharp
// 1. 实例化驱动
var driver = new FxLinksDriver();

// 2. 构造参数
var parameter = new FxLinksParameter
{
    PortName  = "COM3",
    Baudrate  = 9600,
    Host      = 1,       // 站号 1
    Timeout   = 3000,
    BatchSize = 64,
};

// 3. 打开通道（可复用同一串口的多个站号）
var node = driver.Open(device, parameter);

// 4. 定义点位
var points = new[]
{
    new ThingPoint { Name = "温度", Address = "D100" },
    new ThingPoint { Name = "压力", Address = "D101" },
    new ThingPoint { Name = "运行", Address = "M0"   },
};

// 5. 批量读取
var values = driver.Read(node, points);

// 6. 写入
driver.Write(node, new ThingPoint { Address = "Y0" }, 1);
```

### 6.3 底层协议直接调用（供高级用户）

```csharp
// FxLinks 直接使用
using var fx = new FxLinks { PortName = "COM3", Baudrate = 9600 };
fx.Open();

// 读取 10 个字（D100~D109）
var words = fx.ReadWord(1, "D100", 10);   // Byte host, String address, Int32 count

// 读取 8 个位（M0~M7）
var bits = fx.ReadBit(1, "M0", 8);        // returns Byte[]

// 写入位
fx.WriteBit(1, "Y0", new Byte[] { 1 });

// MCProtocol（待实现）
using var mc = new MCProtocol { Address = "192.168.1.10:6000" };
mc.Open();

// 读取 D100 起 10 个字
var words = mc.ReadWords(DeviceCode.D, 100, 10);    // returns UInt16[]

// 读取 M200 起 16 个位
var bits = mc.ReadBits(DeviceCode.M, 200, 16);      // returns Boolean[]
```

## 8. 关键流程

### 8.1 FxLinks 批量读取流程（已实现）

```
FxLinksDriver.Read(node, points)
    │
    ├── GetAddress(point) × N           ← 解析各点位地址
    │
    ├── BuildSegments(points)           ← 按类型分组 + 地址排序 + 区间合并
    │   └── 输出：List<Segment> {start, count, points[]}
    │
    ├── foreach segment:
    │   ├── Thread.Sleep(BatchDelay)    ← 可选批间延迟
    │   └── FxLinks.ReadBit/ReadWord(host, address, count)
    │       ├── 构造 FxLinksMessage (ENQ + BR/WR)
    │       ├── message.ToPacket()      ← ASCII 帧序列化
    │       ├── SerialPort.Write()
    │       ├── SerialPort.Read()       ← 等待响应（Timeout ms）
    │       └── FxLinksResponse.Read() ← 解析 STX/ACK/NAK
    │
    └── Dispatch(segments, results)     ← 将汇聚数据切分到各点位
```

### 8.2 MC 3E 批量读取流程（规划）

```
MCDriver.Read(node, points)
    │
    ├── ParseAddress(point) × N         ← 解析类型（DeviceCode）+ 编号
    │
    ├── BuildSegments(points)           ← 按软元件代码分组 + 地址排序 + 区间合并
    │   └── 输出：List<MCSegment> {devCode, start, count, points[]}
    │
    ├── foreach segment:
    │   ├── Thread.Sleep(BatchDelay)    ← 可选批间延迟
    │   └── MCProtocol.ReadWords/ReadBits(devCode, start, count)
    │       ├── 构造 MCMessage (3E帧头 + 0401h命令)
    │       ├── message.ToBytes()       ← 二进制帧序列化（Little-Endian）
    │       ├── TcpClient.GetStream().Write()
    │       ├── TcpClient.GetStream().Read() ← 等待响应
    │       └── MCResponse.Parse()     ← 解析 D000h 响应，检查结束码
    │
    └── Dispatch(segments, results)     ← 将汇聚数据切分到各点位
```
