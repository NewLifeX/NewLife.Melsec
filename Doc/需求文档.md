# NewLife.Melsec 需求文档

## 1. 背景与目标

### 1.1 背景

三菱 PLC（MELSEC 系列）是工业自动化领域的主流设备，广泛应用于制造、冶金、交通、水处理等行业。上位机程序与三菱 PLC 通信时，主要面临两类协议场景：

- **FxLinks（计算机链路协议，RS-485 串口）**：主要用于 FX 系列 PLC，通过串口通信，适合低成本、短距离场景。该协议已在本项目中完整实现。
- **MC 协议（MELSEC Communication Protocol，以太网）**：主要用于 Q 系列、iQ-R 系列及带网口模块的 FX3U/FX5U 等，通过 TCP/IP 通信，是当前主流工厂部署方案。该协议尚未实现。

NewLife.Melsec 作为 NewLife 物联网生态（[NewLife.IoT](https://github.com/NewLifeX/NewLife.IoT)）的三菱 PLC 驱动库，目标是提供统一、高性能、纯托管的三菱 PLC 通信实现，支持 ZeroIoT 平台与 IoTEdge 网关。

### 1.2 目标

**成功标准（可衡量）**：

1. 覆盖三菱 PLC 两大主流通信协议（FxLinks 串口 + MC 以太网），实现位/字的读写操作
2. 完全符合 `NewLife.IoT` 的 `IDriver` 接口规范，可无缝接入 IoTEdge 网关
3. 纯托管实现，MIT 开源协议，无任何商业许可依赖
4. 单元测试覆盖核心协议帧编解码与驱动逻辑
5. 文档清晰，具备快速上手示例

### 1.3 范围说明

本项目专注**通信协议层**和**驱动层**，不包含 PLC 编程、PLC 配置，以及与具体业务系统的集成。

## 2. 用户角色

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| IoT 平台开发者 | 开发 ZeroIoT / IoTEdge 网关接入层 | 遵循标准 `IDriver` 接口，直接挂载即用 |
| 工业自动化工程师 | 在上位机中与三菱 PLC 通信 | 简洁 API，5 行代码实现读写，串口和网口均支持 |
| 嵌入式开发者 | 在 Linux/ARM 边缘设备上采集 PLC 数据 | 纯托管、多平台（net8 / netstandard2.1） |
| 三方系统集成商 | 将 PLC 数据接入 SCADA / MES 系统 | 稳定可靠，支持批量读取，可配置超时与重试 |

## 3. 功能需求

### 3.1 M1 FxLinks 计算机链路协议（RS-485 串口）

- **描述**：三菱 FX 系列 PLC 专用串口通信协议，通过 RS-485 串口与 PLC 进行位/字数据读写
- **用户故事**：作为工业工程师，我希望通过串口与多台 FX 系列 PLC 通信，以便在不添加任何网络模块的情况下采集生产数据
- **验收条件**（AC）：
  - [x] 支持 BR（位读取）、WR（字读取）、BW（位写入）、WW（字写入）四种操作命令
  - [x] 请求帧格式：`ENQ(05) + 站号(2字节) + PLC号(2字节) + 命令(2字节) + 等待(1字节) + 地址(5字节) + 点数/数据 + 校验和(2字节)`
  - [x] 响应帧解析：STX(02)读响应、ACK(06)写确认、NAK(15)写失败含错误码
  - [x] 校验和计算：所有字节 ASCII 码累加取低 8 位，16 进制表示
  - [x] 支持寄存器地址：X（输入位）、Y（输出位）、M（辅助继电器）、D（数据寄存器）等
  - [x] 支持多站号（多 PLC）共享同一串口连接
  - [x] 驱动层实现批量读取优化（BatchSize / BatchStep / BatchDelay 参数）
  - [x] 完整单元测试覆盖帧编解码与驱动逻辑
- **优先级**：Must（已完成）

---

### 3.2 M2 MC 协议 3E 帧（以太网，二进制模式）

- **描述**：三菱 Qna 兼容 3E 帧格式，用于通过以太网（TCP/IP）与 Q 系列、iQ-R 系列及带网口的 FX3U/FX5U 通信，是当前主流工厂以太网通信方案
- **用户故事**：作为 IoT 平台开发者，我希望通过 TCP 连接读写三菱 Q 系列 PLC 的寄存器，以便将车间设备数据汇入工厂数字化平台
- **验收条件**（AC）：
  - [ ] 实现 Qna-3E 二进制帧完整编解码（子功能码 0000h = 二进制模式）
  - [ ] 请求帧结构：子头 `5000h` | 网络号 | PC 号 | IO 单元号 `FF03h` | 通道号 | 数据长度（LE）| CPU 时钟（0A00h）| 命令（LE）| 子命令（LE）| 请求数据
  - [ ] 响应帧解析：子头 `D000h` | 网络号 | PC 号 | IO 单元号 | 通道号 | 数据长度（LE）| 结束码（0000h=成功）| 响应数据
  - [ ] 支持命令码：批量读取字软元件（0401h）、批量读取位软元件（0401h, 子命令0001h）、批量写入字（1401h）、批量写入位（1401h, 子命令0001h）
  - [ ] 支持软元件类型：D（数据寄存器）、M（辅助继电器）、X（输入位）、Y（输出位）、W（链接寄存器）、L（锁存继电器）、B（链接继电器）、F（报警继电器）、TN/TC（定时器当前值/线圈）、CS/CC（计数器）、R（文件寄存器）、ZR（扩展文件寄存器）、SM（特殊继电器）、SD（特殊寄存器）
  - [ ] TCP 长连接管理（连接复用、断线重连）
  - [ ] 实现 MCDriver（继承 DriverBase，实现 IDriver 接口）
  - [ ] 实现 MCParameter（IP:Port、超时、批量参数）
  - [ ] 驱动层支持批量读取优化（地址合并分段）
  - [ ] 单元测试覆盖帧编解码（至少 8 个测试用例）
- **优先级**：Must（待实现）

---

### 3.3 M3 MC 协议 1E 帧（以太网，旧式 A 系列）

- **描述**：A 兼容 1E 帧格式，用于与老旧 A 系列 PLC 或兼容设备通信，帧格式更简单，不含网络号/PC 号字段
- **用户故事**：作为系统集成商，我希望能接入工厂内尚在服役的三菱 A 系列老式 PLC，以便不需要硬件改造就能读取历史遗留设备数据
- **验收条件**（AC）：
  - [ ] 实现 A-1E 帧编解码（指令格式：子头 `00h`/`80h` | 指令 | 软元件代码 | 起始地址 | 点数 | 数据）
  - [ ] 支持命令：字读（01h）、字写（03h）、位读（00h/02h）、位写（02h）
  - [ ] 实现 MCDriver 扩展支持 1E 模式（枚举参数切换）
  - [ ] 单元测试覆盖帧结构
- **优先级**：Should（规划中）

---

### 3.4 M4 SLMP 协议（3C/4C 帧，现代以太网）

- **描述**：SLMP（Seamless Message Protocol）是三菱最新的以太网通信协议标准，支持 3C/4C 帧，兼容更广泛的设备族（iQ-R/iQ-F 等）
- **用户故事**：作为 IoT 开发者，我希望使用最新 SLMP 协议接入三菱 iQ-R/iQ-F 系列设备，以便获得更好的扩展性和错误处理能力
- **验收条件**（AC）：
  - [ ] 调研 SLMP 与 MC 3E 帧的兼容关系
  - [ ] 决策是否单独实现或合并到 MC 驱动中
  - [ ] 完成帧编解码实现
- **优先级**：Could（远期规划）

---

### 3.5 M5 地址解析与类型转换

- **描述**：统一地址格式解析，支持多种数据类型转换，兼容 IoT 平台点位定义规范
- **用户故事**：作为 IoT 平台开发者，我希望使用统一的地址字符串（如 `D100`、`M200`、`X1F`）定义点位，以便不同协议的 PLC 点位配置方式保持一致
- **验收条件**（AC）：
  - [x] FxLinks 支持地址格式：`{类型}{十进制编号}`，位软元件 X/Y 使用八进制（如 `X17`）
  - [ ] MC 协议支持地址格式：`{类型}{编号}`，位软元件中 X/Y/B 使用十六进制编号
  - [ ] 支持数据类型：`Bool`、`Int16`、`UInt16`、`Int32`、`UInt32`、`Float`、`Double`
  - [ ] 支持点位中冒号分隔的位域（如 `D100:0` 表示 D100 的第 0 位）
- **优先级**：Must（FxLinks 已完成，MC 待实现）

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| **性能** | MC 3E 单次请求（含网络往返）延迟 < 50ms（局域网环境）；批量读取 100 个点位耗时 < 200ms |
| **安全** | 不允许将内部网络地址或 PLC 状态暴露到公网；所有用户输入须校验（地址格式、范围）|
| **兼容性** | 目标框架：`netstandard2.1 / netstandard2.0 / net461`；MC 协议仅要求 netstandard2.1 以上 |
| **可靠性** | TCP 断线后自动重连；超时可配置；异常携带诊断信息（错误码 + 描述） |
| **可维护性** | 所有公共 API 含 XML 注释；核心帧结构有单元测试覆盖；APM 链路追踪支持 |

## 5. 边界与约束

**不做的事情**：
- 不实现 PLC 编程接口（GX Works 通信协议）
- 不实现 OPC UA/DA 服务器
- 不实现 Modbus 转换（由 NewLife.Modbus 项目承担）
- 不依赖任何商业授权库（包括 HslCommunication）

**已知限制**：
- FxLinks 帧格式为 ASCII 编码，通信速率受限（通常 9600bps）
- MC 1E 帧不支持超过 256 个字的单次读取
- 不同三菱 PLC 系列支持的软元件范围有差异，本项目以 Q 系列为主要参考

**技术债务**：
- `MelsecDriver.cs`（MC 协议骨架）已从 `.csproj` 编译中排除，因依赖商业授权的 HslCommunication；需重写纯托管实现

## 8. 术语表

| 术语 | 定义 |
|------|------|
| FxLinks | 三菱计算机链路协议（RS-485 串口），适用于 FX 系列 PLC |
| MC 协议 | MELSEC Communication Protocol，三菱以太网通信协议 |
| 3E 帧 | Qna 兼容 3E 帧，支持 Q/iQ-R/L/FX5U 系列，子头 5000h |
| 1E 帧 | A 兼容 1E 帧，支持 A/FX3U 系列，结构更简单 |
| SLMP | Seamless Message Protocol，三菱最新以太网协议标准（3C/4C 帧）|
| ENQ | Enquiry，询问帧，FxLinks 请求起始字节（0x05） |
| STX | Start of Text，FxLinks 读响应起始字节（0x02） |
| ACK | Acknowledge，FxLinks 写确认响应（0x06） |
| NAK | Negative Acknowledge，FxLinks 写失败响应（0x15） |
| 软元件 | 三菱 PLC 内部存储单元的统称，包括位软元件（M/X/Y）和字软元件（D/W/R） |
| IDriver | NewLife.IoT 驱动接口，统一各类设备驱动的读写行为 |
| DriverBase | NewLife.IoT 驱动基类，提供批量读取优化通用实现 |
| BatchStep | 批合并步长：两点位地址差 ≤ BatchStep 时合并为同一批请求 |
| BatchSize | 单批最大点位数，0 表示不限制 |
| BatchDelay | 相邻批次请求之间的延迟时间（毫秒） |
