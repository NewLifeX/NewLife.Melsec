# NewLife.Melsec 竞品分析报告

> 版本：v1.0 | 日期：2026-07-22

## 1. 概述

本报告对比 NewLife.Melsec 与市面上主流的三菱 PLC 通信 .NET 库，覆盖 FxLinks 串口协议、MC 协议 3E 帧、SLMP 协议等能力域，从功能覆盖、性能、依赖、许可等维度进行综合评估。

NewLife.Melsec 定位为**轻量、纯托管、MIT 开源**的三菱 PLC 通信库，是 NewLife 物联网生态（NewLife.IoT）的三菱 PLC 驱动组件，通过统一的 `IDriver` 接口可无缝接入 ZeroIoT/IoTEdge 网关平台。

## 5. 差距分析

### 5.1 本项目优势领域

| 优势 | 说明 | 领先竞品 |
|------|------|---------|
| **FxLinks 串口协议完整实现** | 唯一在 NuGet 上独立完整实现 FxLinks（BR/WR/BW/WW）的 .NET 开源库 | 全部竞品 |
| **多站号引用计数共享连接** | FxLinksDriver 按串口名唯一复用连接，引用计数管理生命周期 | 全部竞品 |
| **IoT 生态原生集成** | IDriver 接口标准、APM 链路追踪、即插即用接入 IoTEdge/ZeroIoT | 全部竞品 |
| **批量读取分段优化** | BuildSegments 自动合并相邻地址 + BatchSize/BatchStep/BatchDelay | 全部竞品 |
| **跨平台支持最广** | net45~net10.0 9 个目标框架 | HslCommunication（net20+）除外 |
| **纯托管 MIT 开源** | 无任何商业授权依赖 | HslCommunication（商业） |
| **单元测试覆盖** | 119 个测试用例覆盖协议编解码和驱动逻辑 | 多数竞品无公开测试 |

### 5.2 差距领域与追赶优先级

| 差距 | 优先级 | 说明 | 追赶建议 |
|------|:----:|------|---------|
| **MC 3E ASCII 模式** | 🔴 高 | 部分旧设备只支持 ASCII 模式，当前仅支持二进制 | 在 MCMessage 中添加 ASCII 模式分支，DeviceCodes 增加 ASCII 码映射 |
| **MC 1E 帧（A 系列）** | 🟡 中 | 已有规划但尚未实现，A 系列 PLC 在工厂仍有存量 | 按需求文档 MC-1E-1/MC-1E-2 规划实现 |
| **SLMP 协议（3C/4C 帧）** | 🟡 中 | 远期规划，iQ-R/iQ-F 最新设备首选 SLMP | 调研 SLMP 与 3E 兼容关系后确定实现路径 |
| **UDP 传输支持** | 🟡 中 | MC 协议支持 UDP，但当前仅实现 TCP | MCProtocol 增加 UDP 传输模式 |
| **远程控制（RUN/STOP）** | 🟢 低 | 是扩展功能而非核心读写能力 | 在 MCProtocol 中添加远程控制命令 |
| **标签名（Tag）访问** | 🟢 低 | 是上层封装而非协议层功能 | 可在 NewLife.IoT 层面提供点位名映射 |
| **Reactive API** | 🟢 低 | 与 NewLife 同步 API 风格不符 | 无需追齐 |

### 5.3 竞品可借鉴功能

| 竞品 | 可借鉴功能 | 理由 |
|------|-----------|------|
| **McpX** | 随机读取（Random Read） | 离散点位场景无需多次请求 |
| **PlcComm.Slmp** | PLC Profile 约束模型 | 编译时检查可用操作，减少无效通信 |
| **MitsubishiRx** | 串口 MC 协议（1C/3C/4C） | MC 协议也支持串口传输（非 FxLinks） |

## 6. 结论与建议

### 6.1 市场定位

NewLife.Melsec 在以下场景具有**独特竞争力**：

1. **需要 FxLinks 串口通信**的 FX 系列 PLC 项目 → 唯一完整开源实现
2. **需要 IoT 平台集成**的边缘计算项目 → IDriver 原生接入 NewLife 生态
3. **追求 MIT 开源 + 跨平台**的嵌入式/边缘设备 → net45~net10.0 全覆盖
4. **需要批量采集优化**的大规模点位项目 → BuildSegments 唯一支持

### 6.2 优先补齐建议

| 优先级 | 功能 | 预期收益 |
|:----:|------|---------|
| **P0** | MC 3E ASCII 模式 | 消除兼容性盲区，覆盖 Q 系列 ASCII 设备 |
| **P1** | MC 1E 帧（A 系列） | 覆盖老旧 A 系列 PLC 存量市场 |
| **P2** | UDP 传输 | 满足高性能/UDP 场景需求 |
| **P3** | SLMP 协议 | 跟上三菱最新协议标准 |

### 6.3 不建议追齐的功能

| 功能 | 原因 |
|------|------|
| HslCommunication 的多品牌 PLC 覆盖 | 违背 NewLife 按品牌独立项目（Modbus/Melsec/Omron）的架构哲学 |
| Snet 的全套工业协议栈 | NewLife 采用多项目分治，不合并单一巨包 |
| MitsubishiRx 的 Reactive API | NewLife 生态以同步 API + APM 埋点为主，异步风格不一致 |
| 商业授权模式 | 本项目坚持 MIT 开源，不收费 |
